# Hano 0.1.0

First stable release of **Home Assistant Notification Orchestrator**. Requires
Home Assistant 2026.10 or newer. Available through a HACS custom repository.

## Notification orchestration

- Configure messages, recipients, channels, availability, priority, and buttons
  directly in Home Assistant automations with `hano.send`, `hano.preview`, and
  `hano.resolve`.
- Route mobile notifications to selected residents, people at home or away, or
  the nearest people, including ties, without `proximity` entities.
- Track each destination, wait individually when requested, update an active
  notification, or start a new cycle. Resolution cancels pending deliveries and
  requests clearing on supported destinations.
- Keep active notifications, pending deliveries, expiration, and history across
  restarts without replaying completed sends.
- Send immediate voice announcements and Home Assistant persistent notifications.
- Manage people, rooms, tests, and history in an administrator panel available in
  English, French, and Spanish.

## Since 0.1.0b2

This release promotes the beta implementation without changing its notification
behavior or storage format. It includes the iOS APNs-compatible notification tags
and the panel controls that work over HTTP introduced in 0.1.0b2. Version metadata,
release checks, and installation documentation now identify the stable release.

## Install or update

Add `https://github.com/Gnol86/Hano` as an **Integration** custom repository in
HACS, select **0.1.0**, and download it. Beta visibility is not required. Restart
Home Assistant and reload the Hano panel. Existing Hano configuration and stored
notification cycles are preserved; previously accepted notifications are not
automatically resent.

Hano is not in the default HACS catalogue. Installing it does not convert existing
automations or stop AppDaemon. Follow the
[migration guide](https://github.com/Gnol86/Hano/blob/v0.1.0/docs/migration.md)
for a separate, controlled migration.

## Delivery and platform limits

A successful action means the downstream call was accepted, not that a person
received or read the notification. Mobile clearing and global resolution after a
swipe depend on Companion events and platform support. Critical priority requires
device permissions and does not override the separate sleep setting. Voice is
immediate only; reminders and escalation remain in your automations.
