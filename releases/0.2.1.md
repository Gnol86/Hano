# Hano 0.2.1

Allow automations to resolve notification identifiers before their first send or
after history cleanup. Requires Home Assistant 2026.10 or newer.

- `hano.resolve` now succeeds without effects when no cycle exists. Its optional
  response contains `notification_id`, `cycle_id: null`, `status: not_found`, and
  `changed: false`. No notification or cycle is created, no state is written,
  and no notification adapter is called.
- Existing resolved or expired cycles remain unchanged. Active cycles retain
  global resolution, pending-recipient cancellation and remote-clear requests.
  Permissions, unloaded-integration errors, cycle checks and protection against
  old callback buttons remain enforced.
- Document the response contract and update the English, French and Spanish
  action descriptions. Add regression coverage for absent and purged identifiers,
  repeated resolution, other notifications, permissions and concurrent creation.

Update to **0.2.1** through HACS and restart Home Assistant to load the fix.
Existing automations, recipient configuration and stored cycles remain compatible.
Automations can call `hano.resolve` for several identifiers without helpers or
`continue_on_error`, even when some identifiers have no cycle yet.

Validation: 306 Python tests, 41 frontend tests, Ruff, TypeScript and a reproducible
panel build. No physical notifications were sent during validation.
