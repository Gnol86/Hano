# Hano 0.1.0b2

Fixes iPhone notifications rejected by Apple's push service and two panel controls
when Home Assistant is accessed over HTTP. Requires Home Assistant 2026.10 or newer.

## Fixes

- Convert long iOS notification tags to deterministic 64-byte identifiers. The
  previous tags exceeded APNs' limit and caused notifications to be rejected even
  though Home Assistant's mobile notification action returned successfully.
- Use the same converted tag for updates, remote clearing, and correlated mobile
  events. Existing stored cycles remain readable; Android tags and persistent
  Home Assistant notification identifiers are preserved.
- Allow adding rooms and notification buttons over HTTP, where browsers may not
  provide `crypto.randomUUID`.

## Updating

Select **0.1.0b2** in HACS with beta versions enabled, then restart Home Assistant
and reload the Hano panel. Existing configuration is preserved. Previously accepted
notifications are not automatically resent: send a new test, or update the same
logical notification explicitly.

If an iOS notification from the previous beta arrived through local push with a
long tag, dismiss that old notification manually once. Its old on-device identifier
differs from the corrected identifier used for subsequent updates and clearing.

A successful action remains an **accepted call**, not proof of device delivery.
Some Companion transport errors are logged by Home Assistant without failing the
action. Check **Settings → System → Logs** if an accepted notification is missing.

## Validation

- Regression tests cover Apple's byte limit, unchanged short/Android tags,
  content updates, restart without replay, clearing, and stale cycle events.
- Panel regressions cover adding/saving rooms and adding/previewing buttons when
  `crypto.randomUUID` is unavailable.
- A targeted iPhone push using the corrected payload no longer produced the
  APNs identifier-length error in Home Assistant's logs, and its recipient
  confirmed receipt on the phone. This test used the corrected payload through
  the existing Companion service; it did not install the new integration version.
